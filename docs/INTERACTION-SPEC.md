# AstraAgent 交互规范

## 服务商与模型配置

基础接入展示服务商名称、能力类型、地址、密钥与模型目录。模型别名和 API ID 分开保存，价格、上下文、输入能力与路由等级位于“模型规格与价格”中。编辑既有模型时自动打开对应规格。

“高级设置”包含厂商目录匹配、协议、缓存、推理适配与系统提示词。“开发者设置”包含网络信任、流式用量、超时与密钥清除。打开编辑器时这两层默认折叠。自动路由独立折叠，选择 AI 路由后显示 Judge 字段，价格优先时显示比较币种。

保存调用原有后端接口。成功后关闭编辑器并显示保存结果，失败时保留输入和错误信息。无效字段位于折叠区域时先展开祖先分组，再聚焦该字段。关闭编辑器后焦点返回原服务商卡片。自定义下拉列表置于所属模态窗口内，使列表与编辑器共同参与顶层焦点管理。

## 任务状态

| 事件或操作 | 可见状态 | 交互要求 |
| --- | --- | --- |
| 开始 | 正在准备 | 展示请求模型和推理档位 |
| 自动路由开始 | 正在选择模型 | 保留任务状态入口 |
| 路由完成 | 正在执行 | 展示解析后的模型、服务商与原因 |
| 工具开始 | 正在调用工具 | 更新调用次数，详细参数沿用执行记录 |
| 权限请求 | 等待授权 | 通过既有审批入口处理 |
| 模型输出 | 正在生成 / 正在推理 | 保持正文阅读位置，避免整页重建 |
| 用户请求停止 | 正在停止，等待执行器确认 | 取消请求失败时显示错误，保持真实任务状态 |
| 执行器确认取消 | 任务已停止 | 保留输出，并提供检查与继续入口 |
| 完成 | 任务已完成 | 提供交付与执行记录入口 |
| 失败 | 任务失败 | 显示错误，保留记录并提供恢复入口 |

UI 将“请求推理档位”明确标注为请求值，模型适配可能按服务商能力映射。路由原因来自实际路由事件，未知原因保持为空。最终 Token 来自后端按 run ID 聚合的厂商用量。部分调用缺少用量时显示已上报调用数与总调用数，历史缺失数据保持“未上报”。Judge 等携带同一 run ID 的模型子请求计入该任务。

任务状态按会话隔离。重新读取执行日志时重建状态，流式运行期间实时事件拥有当前状态。正文增量沿用既有 Markdown 更新逻辑。任务计时属于普通文本更新，阶段状态提供温和的读屏通知。

恢复使用既有执行检查点与恢复面板。遇到不确定副作用时继续沿用现有确认流程。当前任务面板提供停止与检查后继续，执行器的安全挂起、任意工具暂停仍需后端能力支持，后续实现必须有真实确认事件。

## 键盘与命令面板

| 快捷键 | 行为 |
| --- | --- |
| Ctrl+K / Ctrl+Shift+P | 打开命令面板 |
| Ctrl+, | 打开常规设置 |
| Ctrl+Shift+S | 沿用显示 / 隐藏会话栏 |
| ↑ / ↓ | 在命令结果中移动 |
| Home / End | 结果获得焦点时跳到首尾 |
| Enter | 执行当前结果 |
| Esc | 关闭命令面板并返回原焦点 |

命令面板复用正常页面、设置、工作台与任务控制入口。已有模态窗口打开时，快捷键保持当前窗口操作。结果可使用 Tab 导航。搜索支持当前语言名称、中文原名和显示的快捷键，无结果时提供文字反馈。

## 验收与回归

新增交互先验证正常入口，再验证失败、取消、重试、会话切换和键盘路径。窗口尺寸、主题和材质影响布局时，保存测试截图与对应参数。发布说明中记录验证范围与剩余工作。[UI/UX 验收记录](UI-UX-ACCEPTANCE.md)

## 应用框架与设置导航

设置页标题固定在内容区上方，分类和内容各自滚动。分类中的方向键、Home 与 End 移动焦点，Enter 打开分类。搜索过滤后至少保留一个可见分类的 Tab 入口，搜索框中的向下键进入分类。

窗口宽度不超过 680 CSS px 时，分类改为可收起抽屉。打开时移动到当前分类，Esc 收起抽屉并返回分类按钮，点击分类后移动到页面标题。收起的导航具有 inert 状态。主导航选中项随设置、个人资料和插件管理页面同步，关闭设置后恢复原页面。

服务商编辑保留原来的表单、值、校验与保存处理，标题、内容滚动区和底部操作区分开布局。打开新的服务商卡片只初始化用途，初始化本身不会标记未保存修改。保存按钮在短窗口与滚动期间保持可见。模型显示名称、实际 ID 和规格编辑沿用同一份草稿状态。

插件、Skills、MCP 和 Tools 页签使用一个 Tab 入口，左右方向键与 Home/End 切换页签。第三方插件缺少专属图标时显示内置立方体图标。

宽度不超过 600 CSS px 时，文件、编辑、视图和帮助四组命令进入应用菜单。菜单动作继续调用原有处理，Esc 和外部点击可以关闭。窗口拖动和系统按钮继续通过现有原生桥接处理。

## 阅读空间与皮肤

空白对话输入框以 36 px 文本行起步。上下文压缩位于对话选项中，长输入仍可增长。任务栏默认收起时仍可从顶栏打开。插件、皮肤、权限、流式处理和原生窗口控制继续使用原有状态所有者。

皮肤扩展放在独立的 skins 样式层。主题、强调色、圆角、图标包、布局和快捷控件通过既有声明式入口应用。增强阅读对比度与减少动效继续独立生效。

## V3.14 导航与披露规则

六组设置使用组级导航和组内页签。深层调用仍接受原来的页面 ID，打开本地记忆、语音或归档时会定位所属组及页面。分类搜索涵盖组名和子页面名，方向键与 Tab 入口根据过滤结果同步。

输入区的添加菜单承载附件、项目、审查和上下文压缩。权限模式在输入区保持可见，点击进入权限配置。全局权限下拉沿用原有策略按钮动作，完全访问仍使用原确认流程，取消后恢复实际已保存值。

扩展管理的扫描、创建、导入和市场入口统一放入管理菜单。技能与 MCP 的编辑表单默认折叠，选择编辑时展开相应表单，再执行既有编辑处理。

个人资料以只读视图起步，统计和 Token 活动图位于使用统计分组。语言选择直接可见，导入与扫描语言包位于管理语言包分组。材质与色彩设置位于高级外观中。

窗口菜单的四组动作由单一应用菜单承载。历史按钮在窗口工具栏初始化后同步，初始路由无需等待后续脚本的声明。
