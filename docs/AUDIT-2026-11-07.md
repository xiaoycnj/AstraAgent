# V2.9 审计复核与 V3.2.0 修复记录

复核对象是用户提供的《AstraAgent-V2.9.0-P0-安全与性能审计报告》，原报告基线为 `27f6571`。本次修复应用于 V3.1.1 之后的源码。没有执行报告中未随附的 PoC 文件；以下证据来自仓库新增的合成回归、浏览器和原生窗口测试。没有调用付费模型或执行恶意宿主命令。

## 本机合成基准

执行 `python scripts/benchmark_audit.py`，临时目录中的 500×20000 字节文件、150 条事件、300 条审计记录。单次墙钟结果用于复核改动，不是跨设备性能保证。

| 项目 | 对照 | 修复后 |
| --- | ---: | ---: |
| 旧式上限长度读取循环 / 新的完整扫描 | 1423.09 ms | 471.52 ms |
| 无额外验证变化时的一轮扫描次数 | 报告中 4 次 | 实测 2 次 |
| 150 条事件持久化 | 1306.95 ms | 68.41 ms |
| 同批事件的数据库连接数 | 150 | 1 |
| 全工具 schema / 默认首轮 schema | 17074 字符 | 2305 字符（7 个工具） |
| 300 条审计的 fsync 次数 | 原方案每条一次，共 300 次 | 103 次，含最后 flush |

读取对照只包含旧式读取和散列循环，而新扫描包含路径遍历、边界和变更检查，不将其包装为等价全流程加速倍数。相同机器上的杀毒、磁盘缓存和其他进程会影响结果。

## Windows 11 原生窗口

`native_frame.py` 在应用窗口上安装原生消息子类，保留自定义标题栏，同时恢复 CAPTION、THICKFRAME、MINIMIZEBOX、MAXIMIZEBOX 与系统菜单样式。DWM 过渡不再被禁用，标题栏拖动使用原生 caption drag。最大化时依据当前显示器 `rcWork` 计算客户区，保留任务栏空间；按窗口 DPI 处理边缘和最大化按钮区域。最小窗口宽度为 480 逻辑像素，便于分屏。

原生独立数据目录实测：工作区 `[0,0,1920,1032]`，最大化客户区同为 `[0,0,1920,1032]`；原生非客户区回调确实执行；最大化按钮命中测试返回 `HTMAXBUTTON=9`。原生缩放、最小化样式存在，GUI 没有附加控制台。测试覆盖启动、最大化/还原和最小化；没有测量动画帧率，也没有逐一验证所有多屏/DPI/自动隐藏任务栏组合。动画还会遵循 Windows 的系统设置。

实现依据：[Microsoft Snap Layout 自定义标题栏要求](https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/ui/apply-snap-layout-menu)；[WM_GETMINMAXINFO 官方说明](https://learn.microsoft.com/en-us/windows/win32/winmsg/wm-getminmaxinfo)。采用本项目自己的消息适配代码，没有修改第三方 WebView 源码。

## 验证入口

- `tests/test_audit_p0.py`：来源、仓库指令、权限上限、终端、追加事件、扫描、审计失败、分页/缓存、ACL 降级、记忆成本。
- `tests/test_projects.py`：实际文件修改、验证与回滚，拒绝将 AGENTS 文本放回 system。
- `tests/test_resume.py`：HTTP 断开、续读、游标、幂等提交。
- `tests/browser_security.cjs`：稳定历史节点、任务编辑原文、独立页面与设置、CSP 等浏览器链路。
- `desktop.py --smoke --data-dir <独立目录> --port 0`：原生窗口边界与样式证据。

本次修改不提供操作系统级沙箱，也不承诺彻底消除模型提示注入。安全敏感调用依赖服务端权限、持久化来源和真实批准，不依赖模型自行遵守文字约束。
