# 可恢复执行与依赖任务

AstraAgent 的事件续读与执行恢复是两个独立功能。断开浏览器时，后端继续工作，客户端按游标读取事件；后端进程结束后，执行检查点允许用户明确选择继续任务。

## 使用

重新启动后打开原会话，输入框上方会显示“有一个任务可以继续”。展开查看模型、工具和子任务步骤，点击“继续任务”。已经完成的模型请求和工具调用复用已保存结果；等待批准的调用重新产生一次审批，旧批准不能重用。恢复使用当前服务商凭据，权限不能高于原任务或当前服务端策略。

如果显示“结果不确定”，先核对实际文件、终端或外部服务。可以明确选择重试，或跳过并让模型收到“结果未知，不能声称成功”。跳过不会自动撤销已经发生的修改；重试可能产生第二次修改。任务恢复不会在启动时自动发起付费模型请求。

会话已有后续消息或项目绑定路径改变时，拒绝恢复旧任务，避免覆盖新的进展。可打开检查点和执行记录，另开任务处理。

## 保存边界

- 私有 SQLite 中保存原始模型输入快照、模型返回、工具身份指纹、工具结果、动态加载能力及审批阶段。原始输入快照可能含会话、附件、记忆等资料，应按会话私有数据保护；修改资料不会重写已经保存的任务输入。
- 仅白名单请求选项进入检查点，不保存服务商 API Key、OAuth token、活动批准对象或进程句柄。工具参数、返回值和用户输入自身仍可能包含敏感内容，检查点不是脱敏导出文件。
- 工具调用前先提交 executing 意图，返回后再提交结果。执行后、结果提交前的进程故障会留下 unknown。没有外部事务或幂等键时无法承诺 exactly-once，因此此状态必须人工处置，不能自动重试。
- 已完成的调用即使返回错误也会保存，不会因为恢复而静默重跑。用户可明确重新布置失败工作。网络失败、未保存完整响应的模型请求可以重新请求，因此可能再次计费。
- 回复和用户消息在同一事务中保存，恢复时更新同一回复，避免重复插入。项目最终验收与额外记忆提炼也有步骤记录；验收后文件变化会拒绝使用旧验证结果。
- 当前版本的恢复适用于带 request_id 的持久化聊天路径，桌面/Web 默认采用此路径。旧版任务、一次性非持久化调用和多人格审查不具备此执行检查点。停止任务后可手动继续，启动不会自行恢复已取消任务。
- 日志、检查点和事件为应用级持久化，不是 OS 沙箱。数据库无法落盘时不能承诺恢复。当前功能没有跨机器接管或分布式一致性保证。

## 子任务依赖

`dispatch_agents` 接收最多六个子任务，并行上限三个。每项可填写 `id`、`depends_on`、`retries`，兼容只填写 name/task 的原调用。

```json
{"tasks":[
  {"id":"inspect","name":"检查","task":"读取文件并列出问题"},
  {"id":"tests","name":"测试","task":"检查现有测试"},
  {"id":"review","name":"审阅","task":"根据前置证据提出修改","depends_on":["inspect","tests"],"retries":1}
]}
```

服务端验证 ID 唯一、依赖存在且没有循环。有依赖的任务只接收前序结果作为参考，前序执行失败会阻塞后续。独立任务完成后立即发事件并释放执行位置，不必等整批结束。子任务有独立的持久化步骤命名空间，恢复父任务时复用完成的子任务；子任务不能递归派发。

`retries` 为 0–2，仅处理临时模型错误 429/502/503/504，不能绕过未知工具结果保护。子任务回答完成只表示模型结束，不代表代码或外部效果已通过验证。画布仍以原有卡片/上下文功能为主；此处 DAG 是后端子任务调度，不声称已有完整可视化工作流编辑器。

## API 与清理

- `GET /api/sessions/:id/executions`：最近二十个未完成执行及步骤状态。
- `GET /api/executions/:request_id`：执行状态，不回传原始上下文和凭据。
- `POST /api/executions/:request_id/resume`：继续，返回后用原 request_id 和返回的 after 游标续读事件。
- `POST /api/executions/:request_id/resolve`：`{step, action:"skip"|"retry", acknowledged:true}`，需先人工核对不确定步骤。

这些接口沿用本地认证、同源与访问控制。`acknowledged` 不是可抵御同用户恶意进程的安全证明。清理完成事件缓存会保留可恢复任务；删除整个会话会级联删除执行检查点。

实现使用 Python 标准库和现有 SQLite，没有新增 LangChain/LangGraph 依赖或复制教程代码。状态与依赖设计参考 easy-langent 第六、七章；不以教学示例替代副作用与恢复边界验证。

验证：`tests/test_durable_execution.py` 覆盖进程强制结束后恢复、命令不重复、结果不确定、重新审批、权限收紧、回复幂等、清理保留、子任务复用、临时错误重试与 DAG 调度；浏览器回归覆盖步骤查看、跳过和继续任务。
