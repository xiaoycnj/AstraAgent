# AstraAgent 内核性能基线

## 复跑

在仓库根目录用 PowerShell 运行。两套脚本均使用临时数据；HTTP 基线只连接本机，模型是固定的模拟服务，不需要 API 密钥。

```powershell
$python = '.\runtimes\python\python.exe'
& $python -B scripts/benchmark_kernel.py --repeat 3 --burst-chunks 800
& $python -B scripts/benchmark_kernel.py --repeat 3 --burst-chunks 800 --trace-sqlite
& $python -B scripts/benchmark_journal.py --runs 7 --chunks 1200 --idle-readers 8
```

HTTP 脚本覆盖短对话、800 片段的长回复、项目编辑和验收、断线续传、取消。报告按同一单调时钟记录从请求发出到本地模型收到请求、客户端读完首帧、客户端读完终态的毫秒数；不测前端渲染。`--trace-sqlite` 另跑，提交计数是包含流式事件插入的 SQL 事务数，不是磁盘 fsync 次数。长场景测的是密集输出，不是超长历史自动压缩。

通过 `--journal-source` 可用同一脚本测可信的旧模块；HTTP 可用 `--report PATH` 保存逐次数据。首次对照的旧模块复制在 `work/kernel-preopt/stream_journal.py`（SHA-256 `1de3d9b8098c7751c0aec9e2436f9a917c7057fad739b8693ad56e108c5a4ac1`）。仅在量旧版本时，可给独立日志脚本加 `--allow-missing-terminal` 记录偶发的 live 终态丢失；它仍验证事件顺序和全部正文。原始 JSON 在 `work/kernel-preopt/`。

## 首次本机结果

Windows，内置 Python 3.14.8。独立 SQLite 压测：一个活跃读取端、八个空闲读取端，1,200 条正文加一条终态，七次中位数。

| 指标 | 旧 | 新 |
|---|---:|---:|
| 活跃写入耗时 | 1,378.162 ms | 484.464 ms |
| 空闲读取端 SQL 查询 | 15,107 | 0（各轮 0–8，包含兜底轮询） |
| 写入提交数 | 1,201 | 1,201 |
| 完整回放 SQL 查询 | 16 | 8 |
| 无并发时完整回放耗时 | 7.108 ms | 7.909 ms |

HTTP 对照每场景三次，单位毫秒。仅报告这台机器的结果：单会话有升有降，样本不足以证明端到端提速。项目场景包含多次模型请求，首个模型请求到正文首帧之间含工具和审批；不能将该差值直接解释为模型首字时间。

重连接口到首帧：30.692 / 29.405 ms。取消接口到终态：85.894 / 90.709 ms。追踪样本中的事务数短/长/项目/续传/取消分别为 5/802/13/6/3，前后相同。

## 变更边界

旧日志在每个提交后唤醒所有连接，现在只唤醒同一请求的读取端，保留 500 ms 兜底轮询。事件页与请求状态在一条 SQL 中读取，避免空页读取与终态提交竞态导致提前结束。保留 WAL、同步级别、每个耐久事件的提交、SSE 游标及终态原子更新；没有合并片段，也没有改变模型、工具、项目或取消逻辑。

对于单会话首字延迟，下一轮可拆分请求配置、历史/附件组装和项目快照来定位约百毫秒的前置路径；需要另测真实超长历史触发压缩的场景。
