# 自动性能统计

打开「设置 → 性能统计」。每次文本模型调用结束后，自动将用量、计时和模型标识保存到本机 `data/usage.sqlite3`。页面默认查看全部历史，可按日期、目标模型、服务商、成功/失败/取消以及模型标识筛选，显示历史趋势、模型对比和每页 50 条的逐次明细。超过 90 天的历史按月展示趋势。页面可见时每 15 秒自动刷新，也可关闭自动刷新或手动刷新；打开页面不会发起模型请求。

## 指标

- **输出吞吐量（含等待）**：服务商报告的输出 Token ÷ 整次上游调用耗时，包括连接、排队、推理与接收输出。聚合采用有效样本的总 Token ÷ 总耗时，不取每次速度的算术平均，也不代表并发服务器总吞吐量。
- **流式生成速度（近似）**：输出 Token ÷ 首段非空输出至调用完成的耗时，至少收到两段非空输出才计算。服务商的输出计数可能包括不可见推理 Token，首段之前的推理和流分块方式会影响结果。
- **首段延迟**：请求开始至首个文本、推理文本或工具参数增量的时间；非流式以及完整 JSON 回退没有可测首段延迟。显示 P50 / P95、平均值与样本数。
- **模型标识一致率**：上报标识与目标标识完全一致的调用数 ÷ 已上报标识的调用数。别名、日期后缀、流内标识变化都归为不同；未上报不计入分母。

`选择 → 目标 → 上报` 分别表示用户选择（例如 AutoRouter）、实际请求的目标模型、上游响应 `model` 字段。AutoRouter 的正常选模不计为不一致。这里只核对上游自述的标识，不验证模型的真实身份。

历史用量通过新增可空字段原地迁移，缺少计时和模型标识的旧记录标为未知，不从会话总时长反推生成速度。速度仅聚合成功、输出 Token 为正且具有正耗时的调用；失败/取消保留已报告用量。可统计 Chat Completions、Responses（含 OAuth）和 Claude Messages 协议，包含工具循环、Judge、压缩、记忆和连接测试子请求；图像和视频生成不在统计范围。

如果未报告 Token，用量不会估算；可在服务商的开发者设置中开启「请求流式 Token 用量」，需要接口支持 `stream_options.include_usage`。记录不包含提示词、生成内容、API Key 或完整接口地址。

## 本地接口

`GET /api/performance` 复用应用认证。查询参数：`start` / `end`（本地日期，包含结束日）、`offset`（UTC 时差分钟，-840～840）、`model`、`provider`、`status`（completed / failed / cancelled）、`identity`（same / different / unknown）、`page`（从 0 开始）。返回汇总、分模型统计、趋势、最多 50 条明细及页数。只包含调用元数据。
